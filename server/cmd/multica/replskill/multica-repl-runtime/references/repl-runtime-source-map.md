# REPL runtime source map

Each line maps a contract taught in SKILL.md to the Go code that implements it.

- `server/cmd/multica/cmd_runtime_repl.go` registers `runtime repl`, `runtime next`, and `runtime result`, and installs this skill into `~/.claude/skills/multica-repl-runtime/`.
- `runtime repl` installs the skill, then runs the daemon in the foreground in repl executor mode via `startDaemonForeground(cmd, "repl")` (`server/cmd/multica/cmd_daemon.go`).
- `runtime next` GETs `http://127.0.0.1:<port>/runtime/next?wait=<seconds>` on the daemon loopback (port = `MULTICA_DAEMON_PORT`, then the persisted job-auth `daemon_port`, then `healthPortForProfile`) and prints `{"job": ...}`. The daemon holds the request open up to the wait window — default 300s, max 1800s (`defaultRuntimeNextWait` / `maxRuntimeNextWait` in `health.go`). `--block` makes the CLI re-chain polls internally (`runRuntimeNext` loop calling `pollRuntimeNext`) and return only when a real job arrives, so an idle session never re-wakes the model; Ctrl-C ends the loop cleanly via `signal.NotifyContext`. In `--block` the loop retries only *transient* failures (connection refused / 5xx during a daemon restart); a *permanent* failure — 503 (daemon not in repl executor mode) or any 4xx — is classified by `pollRuntimeNext` as a `permanentNextError` and returned immediately so the session stops with a clear message instead of looping forever.
- `runtime next` also persists the job's task-scoped credential — carried out-of-band in the response `auth` object (`runtimeJobAuth` in `health.go`), never printed — to `<cwd>/.multica/job-auth.json` (mode 0600) via `writeJobAuth`. `resolveToken`, `daemonLoopbackPort`, `newAPIClient`, `resolveWorkspaceID`/`inAgentExecutionContext`, and `runRepoCheckout` fall back to this file (`loadJobAuth`) so every `multica` call in the job authenticates and scopes as the agent, matching the headless env (`MULTICA_TOKEN` etc.). This is what fixes the 403 on agent-only endpoints (e.g. `squad activity`) and unblocks `repo checkout` in repl mode.
- `runtime result <job-id>` POSTs `{job_id, status, summary, error}` to `http://127.0.0.1:<port>/runtime/result`, reports whether it was delivered, and removes the persisted job-auth file (`removeJobAuth`) since the job is over.
- `runtime renew <job-id>` POSTs `{job_id}` to `http://127.0.0.1:<port>/runtime/renew` to extend the job's lease during long work.
- `server/internal/daemon/health.go` serves `/runtime/next` (long-poll via `replBroker.Next`), `/runtime/result` (`replBroker.Report`), and `/runtime/renew` (`replBroker.Renew`) on the same loopback listener as `/health` and `/repo/checkout`; all return 503 unless the daemon runs with `--executor repl`.
- `server/internal/daemon/broker.go` is the in-process broker: `Submit` (called by the repl backend) enqueues a job and blocks for a result; `Next` hands one job to one REPL session and starts its lease; `Report` routes the result back. Job ids are broker-generated (`job-<n>`), not Multica task ids, so a retried task cannot collide.
- Lease/visibility timeout: a delivered job whose lease elapses without a `Report` or `Renew` is re-enqueued by `runReaper` (`reapExpired`), so a dead session's task is recovered by another session. Lease default `DefaultRuntimeReplLease` (30m), set via `--repl-lease` / `MULTICA_RUNTIME_REPL_LEASE`. `Renew` extends the lease for live long-running sessions.
- `server/pkg/agent/repl.go` is the `repl` agent backend: instead of spawning `claude -p`, it calls `Config.ReplBroker.Submit` and emits periodic status beats so the daemon idle watchdog does not kill a task while a human works it. It copies the task-scoped context (`MULTICA_TOKEN`, `MULTICA_AGENT_ID`, `MULTICA_WORKSPACE_ID`, `MULTICA_AGENT_NAME`) from the daemon-built env into `ReplTask` (`agent.go`) so the broker can forward it to the REPL session.
- `server/internal/daemon/daemon.go` selects the `repl` backend (and wires `ReplBroker`) for every provider when `RuntimeExecutor == ExecutorRepl`; the daemon still registers, claims, heartbeats, checks out repos, builds the prompt, and completes/fails the task as usual.
- `server/internal/daemon/config.go` resolves `RuntimeExecutor` from `--executor` / `MULTICA_RUNTIME_EXECUTOR` (default `subprocess`).
